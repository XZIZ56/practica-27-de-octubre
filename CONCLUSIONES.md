# Conclusiones
**SOAP y XML:** SOAP permite intercambiar información estructurada. XML aporta tipado fuerte y reglas claras.
**WSDL:** Funciona como contrato. Describe exactamente las operaciones y parámetros.
**Contrato vs Invocación:** Consultar WSDL es pedir reglas, invocar es enviar una petición real en XML.
**Router y Middleware:** Separar rutas mantiene escalabilidad. El middleware evita duplicación de código al registrar peticiones.
**SOAP vs REST:** SOAP es ideal para sistemas corporativos/bancarios. REST con JSON para web/móviles por ser ligero.
